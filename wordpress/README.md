# WordPress貼り付けガイド

## 貼る順番

最初に、固定ページを「全幅・サイドバーなし」に設定します。テーマにLP用のテンプレートがあれば使用してください。今回のHTMLにヘッダー・フッターが含まれるので、テーマ側のページタイトル・ヘッダー・フッターは、そのページだけ非表示にします。設定名はテーマによって異なります。

全体を1つの「グループ」ブロックに入れ、そのグループの「高度な設定 → 追加CSSクラス」に `clear-lp-page` を指定します。グループの幅は全幅、ブロック間隔は0にします。以下をそのグループ内に順番に並べます。

| 順番 | WordPressのブロック | 貼り付けるファイル・内容 |
| --- | --- | --- |
| 最初に1回 | カスタムHTML | `00-common-style.html` 全文 |
| 1 | カスタムHTML | `01-sections-01-03.html` 全文 |
| 2 | カスタムHTML | `02-sections-04-06.html` 全文 |
| 3 | カスタムHTML | `03-sections-07-09-and-voices-heading.html` 全文 |
| お客様の声 | 選んだプラグインの専用ブロック、または「ショートコード」ブロック | 実際のプラグインが発行した表示コード |
| 4 | カスタムHTML | `04-sections-11-13-and-footer.html` 全文 |

プラグインがまだなければ、「お客様の声」の位置にはカスタムHTMLブロックを置き、`reviews-fallback.html` を貼ります。確定稿の3件を表示できます。プラグイン稼働後はこの仮ブロックを削除して置き換えます。両方を残すと口コミが二重に出ます。

**4本のHTMLは、それぞれタグを閉じた独立した部品です。** ブロックをまたいで `<div>` や `<section>` を開閉する必要はありません。03の末尾に口コミの見出し、04の冒頭に免責文と予約ボタンが入っています。その間の口コミ一覧だけを先生が更新できます。

## 共通CSS

`00-common-style.html` は最初に1回だけです。プレビューで色やレイアウトが反映されない場合、または保存時に `<style>` が消える権限・設定の場合は、このブロックを外し、代わりに `00-common.css` の全文をサイトの「追加CSS」に貼ってください。両方を入れる必要はありません。

スタイルは `.clear-lp` と専用クラス内に限定しています。他のページの本文・見出し・ボタンへ直接適用される全体CSSは含めていません。ただしテーマ固有の `!important` や固定ヘッダー、全幅制限は、本番テーマ上で調整が必要な場合があります。

日本語フォントもCSS内に埋め込み済みです。フォントの追加インストール・別URLの設定は不要で、通常の本文400、太字700、見出し900の3段階を使います。専用フォント名 `ClearSansJP` の定義だけはCSS共通領域にありますが、適用はLP内です。Google等へのフォント取得通信は発生しません。新たな口コミなど、軽量版にない文字は端末の日本語フォントで表示します。

## 先生が更新する口コミ部分

導入するプラグインは未選定・未インストールです。特定製品のショートコードを架空で埋め込んでいません。

1. 先生が「口コミを追加」から、本文・年代・お悩み・必要なら画像を登録する運用を想定。
2. 一覧の表示件数・並び順はプラグイン側で設定。
3. 表示用の専用ブロックまたはショートコードブロックを03と04の間に置く。
4. この口コミブロックだけをグループ化し、追加CSSクラスに `clear-lp-reviews` を指定。背景・横幅・基本文字サイズをLPに合わせます。
5. 日々の追加はプラグインの管理画面で行い、4本のHTMLは触らない。

ショートコードはカスタムHTMLに埋め込まず、WordPressの「ショートコード」ブロックに貼ります。プラグイン固有のカード・星・余白などは、製品決定後に実際の出力を見て整えます。画像だけのレビューは小さい文字が読みにくいので、本文をテキストでも登録する運用をおすすめします。

## 写真について

HTMLにはアクセス確認済みのGitHub画像URLを入れています。既存画像があるコミットを固定参照するので、mainブランチの写真整理で急に変わらない構成です。現状のままコピーして画像を表示できますが、GitHubへの通信とリポジトリの公開状態に依存します。

本運用では先生のWordPressメディアライブラリへ写真をアップロードし、そのURLに差し替えるのが適しています。ルートの `content/wordpress-settings.json` の `imageUrls` に5枚のURLを登録して `npm run build` を実行すると、全ブロックをまとめて再生成できます。

```json
"imageUrls": {
  "check-posture.webp": "https://先生のサイト/wp-content/uploads/実際のパス/check-posture.webp",
  "profile-onishi.webp": "https://先生のサイト/wp-content/uploads/実際のパス/profile-onishi.webp",
  "selfcare-exercise.webp": "https://先生のサイト/wp-content/uploads/実際のパス/selfcare-exercise.webp",
  "shop-exterior.webp": "https://先生のサイト/wp-content/uploads/実際のパス/shop-exterior.webp",
  "treatment-hands.webp": "https://先生のサイト/wp-content/uploads/実際のパス/treatment-hands.webp"
}
```

上記は設定例です。貼り付け用HTML自体にダミーURLはありません。

## ファーストビュー画像ができたら

`prompts/` のPC用・スマホ用プロンプトを使用します。両画像をメディアライブラリへアップロードし、`content/wordpress-settings.json` の `hero` を設定します。

```json
"hero": {
  "enabled": true,
  "desktopUrl": "PC画像の実際のhttps URL",
  "mobileUrl": "スマホ画像の実際のhttps URL"
}
```

`npm run build` の後、01のHTMLだけ貼り直します。767px以下ではスマホ画像、それより大きい画面ではPC画像を表示します。画像は切り抜かず全体を表示。見出し・補助文はスクリーンリーダー用のHTMLにも残します。予約ボタンは画像とは別の本物のリンクなので、画像内にボタンを描く必要はありません。原稿の長い説明文は画像の下に通常のテキストとして保持します。

まだ生成画像は受領していないので、現在は既存のファーストビューが表示されます。
